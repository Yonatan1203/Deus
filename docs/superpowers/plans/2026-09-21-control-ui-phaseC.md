# Control UI Phase C — Claude sessions tab

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A "Claude" tab that mirrors the terminal Agents view for this instance and lets the operator start, message and stop background Claude Code sessions from the dashboard, through Claude Code's own job CLI.

**Architecture:** one new API module `src/control-ui/api/claude-sessions.ts` over an injected `HostCli` (the `DockerRunner` pattern: one `execFile` site, semaphore 2, timeout, errors mapped) whose binary is the `claude` executable resolved once at boot; routes in `server.ts`; a view `web/control/views/claude.js`. No file under `~/.claude` is opened except the session transcript, which is located from the daemon's own `sessionId` and the cwd slug.

**Tech stack:** Node built-ins, the `claude` CLI (`agents --json --all --cwd`, `logs`, `stop`, `--bg --name=<n> --permission-mode=bypassPermissions [--resume=<sid>] -- <prompt>`), vitest.

**Spec:** `docs/superpowers/specs/2026-09-21-control-ui-scope2-design.md` §"New trust boundary" and §C.

## Global Constraints

- **The dashboard session is the operator's shell.** Browser-started sessions run `--permission-mode bypassPermissions` (operator decision, recorded in the spec). Controls that remain: SSH-only bind + login, typed confirmations, fixed cwd (`PROJECT_ROOT`), fixed argv shapes, name/id/prompt validation, rate limits, audit with prompt hashes, read-only refusal.
- **No shell.** `execFile(CLAUDE_BIN, argv, { cwd: PROJECT_ROOT, env: allowlist, timeout })` only; argv elements are literals plus validated `id`/`name`/`prompt`. `CLAUDE_BIN` is resolved once at boot by walking `PATH` for `claude` (`which`-equivalent in Node, no shell) and cached; if absent every route answers 503 `{ error: 'claude CLI not found' }`.
- **Env allowlist for spawned sessions:** `PATH, HOME, TERM, LANG, LC_ALL, TMPDIR, XDG_RUNTIME_DIR, SHELL`, every `DEUS_*` variable, and `ANTHROPIC_*`/`CLAUDE_*` only if present in the process env — minus any name matching the house secret vocabulary from `api/logs.ts` (`SECRET_KEYS`, currently module-private — Task 1 adds the `export`: api key, token, secret, password, passwd, credential, authorization). Scope note: a `bypassPermissions` session in the repo can read `.env` anyway; this prevents accidental propagation into transcripts that are re-rendered in the browser, it is not a confidentiality boundary against the session.
- **Only this instance's sessions — enforced on data, not on a flag.** `--cwd PROJECT_ROOT` is an optimization; the control is a post-parse filter that keeps a row only if `realpath(row.cwd)` equals `realpath(PROJECT_ROOT)` or lies under it (`path.relative` not starting with `..`), and the number of dropped rows is audited once per change. `stop`/`message`/`transcript`/`logs` resolve their `:id` through a **fresh, uncached** list (mutations never authorize against the 3 s read cache) and refuse ids not present (404 + `control_ui_claude_refused`). **A failed list is never an empty list:** when `listClaudeSessions` returns `{ error }` (timeout, non-zero exit, unparseable stdout — the parser accepts only stdout whose first non-blank character is `[`), every **id-resolving** route answers `503 { error: 'session list unavailable' }` with `control_ui_claude_refused { reason: 'list_unavailable' }`, and the list route returns `{ sessions: [], unavailable: true, error }` so the view shows an error state, never "nothing is running".
- **`:id` grammar:** routes accept only the 8-hex job id; the session UUID is never taken from a request — it is read from the resolved row (`row.sessionId`).
- **Kind/provenance:** the tab mirrors the terminal Agents view, so `stop` and `message` reach any *background* session under this repo, whether or not the dashboard started it (operator decision). The route refuses `kind !== 'background'` for stop and `!resumable` for message with 409 + `control_ui_claude_refused` — the hidden button in the UI is presentation, not authorization.
- **Validation:** job id `/^[0-9a-f]{8}$/`; session id (internal only) `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/`; name `/^[\p{L}\p{N}][\p{L}\p{N} ._-]{0,59}$/u` (must not start with `-`: the live threat with `execFile` is **option injection**, not shell metacharacters); prompt: string, 1..8192 chars, no NUL; `limit` clamped 1..500 with `clampLines(v, fallback, max)` — Task 1 adds an optional third `max` parameter (default `LOG_LINES_MAX`, so every existing call keeps its 1..1000 contract; `logs.test.ts` gains one case for the override); everything else 400. Every value-bearing flag is passed in `--flag=value` form and the prompt comes after a literal `--` (`['--bg', '--name=<n>', '--permission-mode=bypassPermissions', '--', <prompt>]`, resume adds `'--resume=<sessionId>'`), so no user string can ever be parsed as an option.
- **Read-only = metadata only:** the list (name, kind, state, status, cwd_rel, age) **plus** `waiting_on`; `transcript` and `logs` answer 403 `read-only from the dashboard` exactly like container logs do (`server.ts` Phase 4) — transcripts carry operator prompts and tool-echoed file contents, which the string redactor is only a backstop for; `POST` routes 403 via the mutation gate.
- **Audit:** `control_ui_claude_start {name, promptHash, id}` (the id the CLI printed; a distinct `control_ui_claude_start_unparsed` warn line when it could not be parsed — a start that ran but left no id must still leave a trace), `control_ui_claude_message {id, promptHash, outcome: continued|copied, new_id}`, `control_ui_claude_stop {id}`, refusals `control_ui_claude_refused {id ≤ 64 chars, reason}`; reads audited once per session (`readAudits`). Audit lines go through `logger`, i.e. the service's stdout — on this instance systemd appends that to a file, so the record outlives the process; the in-memory ring is a view of it, not the record. Recording `{promptHash, id}` makes the hash verifiable later against the session's own transcript.
- **Redaction:** `claude logs` output and transcript text pass `redactSecrets` before leaving the process (they are the operator's own sessions, but a pasted token would otherwise be re-rendered).
- **Render contract for the new view:** every CLI-derived string that reaches the view — transcript text, `name`, `status`, `waiting_on`, `error` — is rendered with text nodes only (no markdown, no auto-linking, no `innerHTML`), and the list route's `error` is `redactSecrets(error).slice(0, 200)` before it leaves the process.
- **Cost ceiling:** the start limiter is keyed on a constant (global 3 / 10 min, not per login session, so a re-login does not mint a new budget), and `start` answers 409 `{ error: 'too many live sessions', live }` when 3 dashboard-started sessions are already `working`. Dashboard-started ids are kept in `CONFIG_DIR/control-ui/claude-started.json` (append on start; pruned only after a **successful** list — a failed list never releases the ceiling; a failed ledger write after a confirmed start makes the route answer 500 `{ error: 'ledger write failed', id }` so the operator knows a session exists that the ceiling will not count) — the join key for the ceiling and for a "started here" chip in the UI. It is a **cost guard, not a security control** (a `bypassPermissions` session could rewrite it; the hard bound is the global limiter): unreadable or corrupt ⇒ `start` answers 409 `{ error: 'live-session ledger unreadable' }` rather than assuming zero live. The 409 copy for the ceiling says "3 dashboard-started sessions are already working" so terminal-started ones are understood not to count.
- **Read/stop limiters:** `claudeReadLimiter` 30/min per session over the **list**, `transcript` and `logs` routes together (one budget bounding the tab's total host load per session: the list forks `claude agents`, `logs` forks `claude logs`, `transcript` reads up to 2 MB from disk; the spec's "30/min" is this limiter), and `claudeStopLimiter` 6/min; the view re-fetches on an explicit refresh, `visibilitychange` and the 45 s timer only, never in a render loop.
- Public-repo generic: fixture uses a fake `claude` script; screenshots show fixture names only.

## Design (patterns and data structures)

- **`HostCli`** = `createDockerRunner` generalized: `createHostCli(bin, opts)` in `api/host-cli.ts`, and `docker.ts` becomes a thin re-export (`createDockerRunner = (bin, o) => createHostCli(bin, o)`) so there is still exactly one `execFile` site for host binaries. Build runner keeps its own `spawn` (long-lived child) as today.
- **Session row** (`ClaudeSession`): `{ id, session_id, name, kind: 'background'|'interactive', state: 'working'|'blocked'|'done'|'unknown', status?: string, waiting_on?: string, cwd_rel: string, started_at: number, updated_at?: number, pid?: number, resumable: boolean }` — `resumable = kind === 'background' && !!session_id`. `cwd_rel` is `path.relative(PROJECT_ROOT, cwd)` or `'.'`.
- **`waiting_on`** — the daemon JSON carries no message text (keys observed: `cwd, id, kind, name, pid, sessionId, startedAt, state, status`), so for `state === 'blocked'` it is the last assistant text block, sliced to 500 chars, redacted, served in read-only too (it is metadata about what the operator owes the session). It is computed by `tailAssistantText(file)` = `readTail(file, 256 * 1024)` over one shared `readTail(file, bytes)` contract (also used by `readTranscript` with `2 * 1024 * 1024`): read only the last N bytes, discard the first partial line whenever the read did not start at offset 0, skip lines that fail `JSON.parse` instead of throwing; then scan backwards for the newest primary `assistant` row with a `text` block; memoized per session id on `{ mtimeMs, size }` so an unchanged transcript is never re-read (measured on this host: primary transcripts reach 66 MB — whole-file parsing on a 3 s tick is out).
- **Transcript** (`readTranscript(projectsDir, sessionId, limit)`): located by the session id alone — `readdirSync(projectsDir)` and pick the single `<dir>/<sessionId>.jsonl` that exists (session ids are UUIDs, unique across project dirs); no cwd→slug inference. The candidate is confined with `realpath` under `realpath(projectsDir)`, must be a regular file, and the id comes from the resolved row (never a request), so a request can never name a path. Subagent transcripts live in separate files (`<dir>/<sessionId>/subagents/agent-*.jsonl`, >100 MB on this host) and are excluded **by path** — only the exact `<sessionId>.jsonl` is ever opened; `isSidechain: true` rows are skipped as belt-and-braces. The full read is tail-bounded too: the newest `limit` rows are taken from `readTail(file, 2 MB)` (same partial-line and bad-line rules; a `truncated: true` flag says when older rows exist). Rows: `{ role: 'user'|'assistant', text }` from `message.content` — a plain string becomes one row as-is, an array contributes its `text` blocks — `{ role: 'tool', tool: name, summary: first 120 chars of a `description`/`command`/`file_path` field }` from `tool_use` blocks; `tool_result` and system rows skipped; newest `limit` rows.
- **Spawn result parsing — structural, never prose:** `claude --bg` prints the job id (which is also the first group of the session UUID, so the same value can legitimately appear twice); the parser requires **exactly one distinct** `/\b[0-9a-f]{8}\b/` value across stdout, else the route answers 502 `{ error: 'could not determine the session id' }` and writes the `_unparsed` audit line. For `message`, `continued = printedId === requestedJobId`, otherwise `copied` (a second, autonomous agent now exists — the response and the audit both say so, and the UI shows the new row). Before answering, the route re-lists uncached and confirms a row with that id exists; the ceiling's `claude-started.json` entry is written from that confirmed row (id + `started_at`), not from stdout alone.
- **Poller:** 3 s `agents --json --all --cwd`, only while the Claude tab is in use — a client that fetched `GET /api/v1/claude/sessions` in the last 60 s (the view re-fetches on `visibilitychange` and every 45 s while mounted) — never on global `hub.clientCount()`; a tick is skipped while the previous one is in flight (the `HostCli` semaphore also bounds it); diff on the projected JSON; broadcast `csession`.

## Deviations from the earlier chat scope

- Sessions are listed/stopped through `claude agents --json` / `claude stop`, not by reading `~/.claude/sessions` or signalling pids (the CLI exists and is the supported surface); the CLI's output is treated as untrusted input — filtered on `realpath(cwd)`, ids parsed structurally, kind/resumable re-checked per route.
- Validation is tighter than the spec's first draft and the spec is updated to match: names must start with a letter or digit (`/^[\p{L}\p{N}][\p{L}\p{N} ._-]{0,59}$/u`, option-injection guard) and session ids must be well-formed UUIDs (`8-4-4-4-12` hex), not any 36 hex/dash characters.
- Read-only serves session metadata (incl. `waiting_on`) and nothing from transcripts or logs (threat-model round 1).
- The **list route** answers 200 `{ sessions: [], unavailable: true, error }` when the CLI fails (the SSE poller and the view diff one shape; a route-specific 503 would blank the tab), while every **id-resolving** route answers 503 — the spec's "a failed list is a 503, never an empty list" is met for authorization decisions; the list route carries the failure explicitly instead. Spec wording aligned.
- Transcript row types: anything other than a primary `user`/`assistant` row is skipped (observed on this host: `attachment`, `ai-title`, `cost-state`, `queue-operation`, `file-history-snapshot`, …), stated as an invariant with a test rather than an enumerated skip list.
- Blast radius, stated: the list includes the autonomous pipeline's worktree sessions under this repo; `stop` and `message` reach them, and `message` injects a prompt into a `bypassPermissions` session the dashboard did not start. That is the recorded operator decision ("mirror the terminal Agents view"); the audit line is the only trace of it.
- "Message a session" is `--bg --resume`; the daemon decides continue-vs-copy and the route reports which.
